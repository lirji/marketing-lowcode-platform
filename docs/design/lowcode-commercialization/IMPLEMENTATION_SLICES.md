# 低代码营销商业化实施方案 v1

**首发交付是指定门店商品满减与订单级补贴对账。** 运营可以配置和发布活动，客服可以解释优惠命中及版本，财务可以用真实支付与退款凭证核对逐笔补贴。后续将同一套发布和运营流程扩展到会员专享促销、生命周期触达和邀请获客。

本方案基线为营销 `07393f1`、商城 `cd5ba82`、交易中心 `d85d392`。本轮完成规划与静态准备。试点商户、跨平台业务合同、生产资源预算及上线授权均待各责任方签收。

实施进度见[执行记录](../../delivery/lowcode-commercialization/PROGRESS.md)。LC-01 已完成，LC-02 与 LC-07 的签收缺件见[首发证据与签收准备](../../delivery/lowcode-commercialization/READINESS.md)。

## 1. 首发范围与商业验收

| 项目 | 建议取值 | 签收责任 |
| --- | --- | --- |
| 首发场景 | 一个真实商户、一个授权组织、一个参与门店、指定 SKU、人民币固定满减和一个明确的出资账户。同组织至少一个非参与门店用于范围对照 | 商户运营、营销产品 |
| 订单范围 | 新报价绑定原生交易订单号。使用同一门店的真实支付回执、分次退款回执和财务对账。历史订单另行评估权威映射及回填窗口 | 交易中心、营销资金、商户财务 |
| 运营结果 | 运营能独立完成配置、校验、提审和发布跟踪。客服凭订单号能看到优惠结果、版本及处理状态 | 运营、客服 |
| 财务结果 | 完成约定的关账周期和退款观察窗口。逐笔补贴确认、冲回与权威凭证一致，差异有来源和处理记录。重复记账、超额冲回及未解释资金差异均为零 | 商户财务、营销资金 |
| 试点推广条件 | 签收实测的配置耗时、对账耗时、决策尾延迟、处理成功率和峰值规模，再决定扩店。付费用量候选为成功结算的唯一促销订单，计价及套餐由真实商户验证 | 产品、销售、商户、平台运维 |

首发验收以授权商户的实际交易凭证和可复现的运营操作为准。隔离环境用于校验迁移、回放和故障恢复。性能目标从[仓库候选 SLO](../../operations/SLO_CAPACITY.md)选取并按商户规模签收。

## 5. 验证、发布与回退

1. **每片交付证据。** 固定源码、镜像及迁移版本。记录契约测试、所改模块编译、真实 MySQL 或 Kafka 验证、失败重试和权限隔离。页面改动使用已有工作台样式，以实际操作及桌面、移动截图验收。共享能力修改后验证原调用者。CI 验证精确提交，历史或隔离结果标注环境。
2. **首发前证明结果。** 先对照授权真实历史或受控订单做只读核对。确认门店范围、真实回执来源、资金守恒和数据水位后，以一个授权门店试点。每阶段保留上一稳定版本、启停负责人、观察窗口及可定位的准备回执。
3. **暂停新参与的条件。** 任一重复记账、越权命中、超额补贴或未解释资金差异立即暂停。尾延迟、消费者积压、回执延迟、人群数据过期和渠道重复发送按各阶段签收阈值停止放量。观察期覆盖至少一个约定结算周期和相应退款窗。
4. **分开处理回滚和补偿。** 规则异常时回到已验签的上一个版本；已签报价与已产生订单按原始记录结算。资金异常时冻结新预占并保留入箱，按账本追加冲回后核对。渠道异常时暂停新触达，保留原幂等键，通过回执补查在途请求。应用回退前核对 N/N-1 兼容。人群撤销优先于历史版本恢复。沿用[发布回滚手册](../../operations/RELEASE_ROLLBACK.md)和[容量准入](../../operations/SLO_CAPACITY.md)。

## 6. 联调准备与启动交接

1. **首个可启动的工作是 LC-01。** 复核[订单补贴查询与对账入口](../../delivery/operator-status-accuracy/PROGRESS.md#按订单核对补贴流水)，列出签名报价、回执、绑定、确认、退款、账本和报表的已有证据，按已签约的环境继续核对。输出每类证据的来源、时间、权限、缺项和核对负责人，集中列出 LC-02 需要签收的样本和字段。
2. **试点启动需要商户和财务签收。** 明确商户、授权门店与预定资金账户，指定交易、Auth、资金、财务和运维岗位负责人。机器凭据和实际客户数据进入约定的受控渠道。供应链相关配置的变更在各权威仓库独立审查。
3. **增购按证据排序。** 首店全链路通过后扩店，再叠加会员专享。单渠道 Journey 的实际转化和成本足以证明价值后再扩渠道。邀请有礼在获客客户和权益终态确认后进入生产准入。通用 CDP、复杂折扣图、多渠道全面铺设和 AI 自动生成进入后续机会池。

现有 [S06、S07、S11–S13](../../delivery/completion-20261116/PROGRESS.md) 的编号与历史状态继续保留。LC-07 至 LC-09 消费 S06b 的画像资格边界，LC-10 至 LC-11 复用 S07 和 S11 的触达与发布基础，LC-06 核对 S13 的生产门禁。本文用 LC 编号跟踪四个设计器的商业交付顺序。
