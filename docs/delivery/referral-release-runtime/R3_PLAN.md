# R3 本地激活与熔断切片

2026-09-09。用户在明确提出“持久激活序号、历史制品回滚、熔断校验、并发恢复测试”后回复“继续”，本切片已批准。沿用既有交付技能，UI 不适用。

## 边界

只实现显式内部装配的本地状态机，不增加 HTTP/生产 Bean，也不解除 control/参与拒绝。激活必须同时验证已安装制品和可信 READY 证明 Port；Port 未接通默认拒绝。测试用真实签名与隔离库夹具证明本地机制，不冒充真实 ACK。

KillSwitchDirective 没有健康水位字段：启用熔断持续拒绝，关闭熔断只有在原指令 activatedAt 起算的有界新鲜窗口内可作为本地检查依据，重复投递不得刷新窗口。窗口最多 10 秒，不能据此宣称健康订阅已接通；持续开放仍需未来可信新鲜水位协议。

## 实施

1. 独立签名校验器：activation 绑定已验证 manifest 的 tenant/slot/签名/代次/有效期，稳定路径拒绝 canary；kill 绑定 tenant/namespace/签名，拒绝未来时间。
2. V13 新增 cursor 与不可变 directive audit 两表；本地事务 reserve→FOR UPDATE→比较序号→追加审计→CAS 游标。相同序号同内容幂等，异内容冲突，低序号拒绝；事务失败不得推进游标。
3. 激活读取 V12 原制品重新验签，再读取受信 READY 证明；锁后重验有效期。回滚只允许已保存且仍可信的旧代次，并使用更高 activationSequence。
4. 只提供本地防护检查结果，不构造 ReferralParticipationPermit。检查必须重验保存签名和当前有效期，缺激活、熔断记录、READY 或新鲜依据均拒绝。
5. 真实签名单测和隔离 MySQL：乱序、重复异内容、并发争抢、回滚、异常回滚、重建对象恢复、时间边界/重放不续期、默认拒绝、租户隔离。相关回归后自审、QA、文档和本地提交。

## 验收

- R3-A：错误签名/tenant/slot/绑定/时间无法推进状态。
- R3-B：序号永久单调，原子审计与游标，重启可读。
- R3-C：高序号可选择已安装历史版本，低序号不得覆盖。
- R3-D：熔断打开或依据过期/缺失始终拒绝，重放不刷新。
- R3-E：无 READY 证明不能激活；本地验证通过也不开放参与。

## 配置、CI 与回滚

只在隔离测试 MySQL 执行迁移，所有表/列注释齐全。生产密钥和 READY Port 尚未接线。既有 CI reactor 自动发现新增测试，无新增部署 job。回滚关闭调用入口并保留 cursor/审计表，不降序号、不删事实。
