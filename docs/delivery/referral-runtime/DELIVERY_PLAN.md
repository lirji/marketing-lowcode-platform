# Referral runtime SPI 第一切片

依据交易中心冻结 baseline/10-FINAL_PLAN.md §5、§9.2 与 09-PRODUCTION_DESIGN.md，用户已授权继续原平台和并行实现。使用 deliver-feature-end-to-end 工作流，原设计不重开审批。

本切片可行：新增独立 Java 21 模块及四个公开类型，不依赖数据库、网络或 Spring。确定性输入包含冻结时间、模式、奖励规则、权威证据状态、调用方提供的当前时间。所有运营数值由输入配置，不提供试点默认值。UI 不适用。

| 验收 | 实现/验证 |
|---|---|
| AC-01 | 两种资格模式、数量固定 1、角色与模式及额度/版本严格校验 |
| AC-02 | 半开绑定/资格窗口、退款净额、观察期、迟到宽限、未知证据失败关闭 |
| AC-03 | 双边独立与累计人数阶梯；稳定候选键支持持久层唯一裁决 |
| AC-04 | 无 I/O、副作用、墙上时钟或持久状态；模块专项纯单测 |

按类型/校验→运算→专项测试→复核与文档顺序实施。新增 runtime-spi/referral-runtime-spi/{pom.xml,src/}，只在 runtime-spi/pom.xml 注册模块。既有前端改动不纳入本切片。CI 通过现有根 Maven reactor 注册覆盖；专项命令 `mvn -o -f runtime-spi/referral-runtime-spi/pom.xml test`。不启动服务、不迁移、不提交、不运行全仓库测试。

这是规则候选，不是授权、额度预占或履约。调用方必须完成认证来源/主体/租户关联、证据单调修订、规则冻结、锁后时间复检、风险、持久 reward 唯一身份、取消及已追回档位墓碑。真实会员/首单渠道、退款口径、SKU、时间/保留/生产参数、隐私方案仍待确认。迟到宽限作为必填配置；超宽限输出 REVIEW，不猜测失败终态。
